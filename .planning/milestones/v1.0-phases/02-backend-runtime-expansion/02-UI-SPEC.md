## Typography

Use only these four sizes and exactly two weights across portal-owned UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Supporting / metadata | 14px | 400 | 1.5 |
| Body / controls | 16px | 400 | 1.5 |
| Section heading | 20px | 600 | 1.2 |
| Page heading | 28px | 600 | 1.2 |

Labels and status chips use 14px; labels use 600 only when they introduce a field or group. Buttons use 16px/600. Relay URLs, coordinates, manifest IDs, aggregate hashes, and pubkeys use 14px/400 monospace and are never reduced below 14px. Do not add a display size, weights outside 400/600, or all-caps labels.

## Layout Contract

- Add `Settings` as a full content-row shell destination; preserve the `100dvh` two-row shell and in-flow 64px bottom navigation. The persistent napplet iframe remains mounted and inert/hidden while Settings or Home is visible.
- Keep the existing two-destination bottom navigation unchanged in Phase 2. Enter Runtime settings from a clearly labeled `Runtime settings` action in the Profile view; browser Back returns to Profile without reloading the iframe.
- Settings uses 16px mobile gutters, 24px vertical padding, a 100% width form, and a 40rem maximum content width aligned to the start on wider screens. Do not center labels or form content.
- On Runtime settings, the page heading is the first visual anchor and the `Relay routing` group is the primary content focal point. On Home, the installed-catalog heading and synchronization status establish the first anchor, followed by the start-aligned first card or empty state.
- Group fields into `Relay routing`, `Relay authentication`, and `Blossom servers`. Each group is a white bordered 12px-radius section with 16px mobile padding and a 24px gap from the next group.
- Use one labeled multiline URL-list field per collection: `Fallback and extra relays`, `Default indexer relays`, `Default lookup relays`, and `Blossom servers`; accept one URL per line. Use a labeled single URL field for the optional local relay cache. Place concise help text directly below each label and field-level errors below the affected field.
- Per-relay AUTH opt-in is a list of relay rows, each with a visible canonical URL and a native checkbox/switch labeled `Allow NIP-42 AUTH`. Blocked rows are absent from selectable AUTH choices; if a saved relay becomes blocked, show it disabled with `Blocked — connection and AUTH disabled` until the next successful save removes it.
- The Save action is full width on mobile and intrinsic width on `min-width: 640px`. Keep it in normal flow at the end of the form; do not create a sticky footer that competes with the shell navigation or mobile keyboard.
- Home replaces the single configured tile projection with the synchronized installed catalog. Render one-column cards at mobile widths; from 640px use an auto-fit grid with a 280px minimum and 16px gaps. Each card preserves the current 48px icon/title/status anatomy and adds version metadata plus an overflow actions button.
- Manifest update review uses a native modal dialog no wider than 36rem and no taller than `calc(100dvh - 32px)`. Its comparison body scrolls while heading and actions remain visible. At 640px and above, old/new scalar values may use two columns; at mobile widths they stack old above new.

## Component Inventory

| Component | Contract |
|-----------|----------|
| Runtime settings route | Fresh server-rendered page and POST handler; reads and persists backend-owned settings, with browser code limited to form affordances |
| Settings group | Semantic `fieldset`/`legend` where related controls exist; white bordered card containing labels, help, values, and inline validation |
| URL-list field | One URL per line; preserves entered values after validation failure; canonicalized saved values appear on the subsequent render |
| AUTH relay row | Canonical relay URL plus labeled opt-in control and policy status; blocked state overrides and disables AUTH |
| Cache-health summary | Compact status row for local relay and local Blossom discovery; health never blocks form use or napplet launch |
| Installed catalog grid | Account-owned, stream-updating collection derived from the signed NIP-78 event; supports empty, stale, updating, one, and many states |
| Napplet card | Verified manifest icon/name/version; launch uses the accepted manifest ID; update badge and actions never trust iframe-supplied identity |
| Update review dialog | Shows publisher/coordinate, old and new manifest event IDs, display/version changes, aggregate hash, and changed capability declarations before approval |
| Uninstall dialog | Native destructive confirmation; publishes a replacement catalog without implying immediate artifact deletion |
| Inline status notice | `role="status"` for saved/updating states and `role="alert"` for newly introduced failures; notices do not overlay the iframe |

Do not add a general diagnostics dashboard, capability approval center, multi-account picker, cache browser, or contract-drift report viewer in Phase 2.

## Interaction Contract

1. Opening Runtime settings shows the backend's current persisted snapshot immediately. It does not wait for relay health, NIP-65 data, or Blossom discovery to finish.
2. Saving submits all settings to the backend. While in flight, disable only `Save settings`, label it `Saving…`, and retain all editable values. On success show the saved copy and render the canonical persisted values. On failure retain edits and focus the first invalid field or the summary alert.
3. Settings changes do not claim to restart or reconnect existing work. Copy must say new operations use the values; reactive streams may update naturally without a forced teardown.
4. Cache-health indicators update independently. Degraded local cache displays the documented warning and upstream fallback; it never disables napplet launch, Save, or catalog interaction.
5. The installed catalog renders the last available projection immediately, then updates in place as valid Nostr state arrives. Never replace populated content with a full-page spinner. Preserve card positions where identity is unchanged.
6. A newer verified manifest adds `Update available` to its card but keeps launching the accepted manifest. Selecting review opens the attested comparison; `Keep current version` closes without mutation. `Approve update` signs/publishes the replacement catalog and closes only after command acceptance, then the projection updates from synchronized state.
7. Changed capability declarations are a line-by-line added/removed list, not color alone: prefix additions with `Added` and removals with `Removed`. An empty diff reads `No capability changes`.
8. Uninstall is available from the card action menu. Confirmation names the napplet and explains cache retention. Disable `Uninstall napplet` while publishing; on error keep the dialog open and show `The napplet could not be uninstalled. Try again.`
9. Concurrent catalog replacement follows latest-valid-event semantics. If the visible catalog changes while a dialog is open, close the stale dialog and announce `The installed catalog changed. Review the latest version before continuing.`
10. Catalog actions requiring a signer are disabled when no active signer is available, with visible support text `Connect a signer to change installed napplets.` Public catalog content remains readable.
11. Browser Back closes an open dialog first, then returns Settings to Profile, then follows the existing shell navigation contract. Escape closes non-destructive review and uninstall dialogs without action.

## Accessibility and Responsive Acceptance

- Validate at 320px, 390px, 768px, and 1440px widths, with a non-zero safe-area inset and with a mobile software keyboard open. No page-level horizontal overflow is allowed.
- Every control has the existing 2px accent focus ring and 2px offset. Focus order follows visual order. Dialog opening focuses its heading or first safe control; closing returns focus to the invoking card action.
- All fields have persistent labels, optional/required semantics, and programmatic error association. URL examples belong in help text, not as placeholder-only labels.
- Status is never conveyed by color alone. Healthy, degraded, blocked, stale, added, and removed states all have text labels. Dynamic non-critical synchronization uses coalesced `aria-live="polite"`; submission and validation failures use `role="alert"` once.
- Card overflow actions have an accessible name containing the napplet name. Icon-only copy/menu controls retain 44px targets.
- Native dialogs trap focus, close on Escape before mutation, and prevent background interaction. Destructive confirmation never preselects or auto-focuses `Uninstall`.
- Respect `prefers-reduced-motion: reduce`; reuse the existing 120ms opacity transition only and do not animate live card reordering, health pulses, or dialog comparisons.
