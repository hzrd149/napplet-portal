Remove dead and duplicated runtime code, and remove the load-time napplet capability gate.

Purpose: `runtime/` has three concrete redundancies (a dead second window bridge, three copies of one atomic-write routine, three overlapping keyed-registry classes) plus a load-time capability rejection path that contradicts the project's negotiation model. Output: two new small runtime modules, one deleted class, one deleted gate, and a net reduction in `runtime/` line count with no behavior change other than the deliberate removal of the load-time rejection path.

Scope guard: no folder moves, no renames beyond those each unit requires, no research. The existing ~90-file test suite is the safety net. Tests are only edited where the behavior they asserted was deliberately removed — and each such edit is named explicitly below.

  <files>runtime/atomic_file.ts, runtime/account_store.ts, runtime/settings_store.ts, runtime/storage_store.ts</files>
  <action>
Three stores carry near-verbatim copies of the same atomic-write routine: `AccountStore.#writeAtomically`, `SettingsStore.#write`, and `NappletStorageStore.#writeAtomically`. All three derive a directory and file name by scanning for the last path separator, build a temp path of the form dot-name-uuid-tmp inside that directory, `Deno.mkdir` the directory recursively with mode `0o700`, write the payload with mode `0o600`, `Deno.chmod` the temp file to `0o600` on non-Windows, `Deno.rename` the temp file over the target, and on any failure best-effort remove the temp file before throwing a store-specific error.

Create `runtime/atomic_file.ts` holding the single shared skeleton. Suggested shape — adjust names if the codebase reads better, but keep the parameterization:

  - `resolveTemporaryPath(path: string): { directory: string; name: string; temporary: string }` implementing the existing separator-scan and uuid-suffixed temp naming, including the current edge cases (no separator yields `"."` as directory, a leading-slash-only prefix yields `"/"`).
  - `writeFileAtomically(options)` performing the shared sequence, parameterized by:
      * `path: string` and `serialized: string`
      * `failureMessage: string` — thrown verbatim as `new Error(failureMessage)` on any failure
      * `durable?: boolean` — when false or absent, write with `Deno.writeTextFile(temporary, serialized, { create: true, mode: 0o600 })`; when true, use the `Deno.open` with `createNew` plus the incremental write loop plus `file.sync()`, and after a successful rename also open the directory and `sync()` it on non-Windows
      * `beforeRename?: () => void | Promise<void>` — awaited immediately before the rename
      * `isCurrent?: () => boolean` — checked immediately before the rename; when it returns false, throw so the standard failure path runs
      * `onCleanupFailure?: () => void` — invoked when best-effort temp removal fails with anything other than `Deno.errors.NotFound`, so each store keeps its own debug namespace and message
