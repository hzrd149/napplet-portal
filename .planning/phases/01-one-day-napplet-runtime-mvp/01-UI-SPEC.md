# Phase 1 — UI Design Contract

> Visual and interaction contract for the one-day Napplet Runtime MVP. Generated by gsd-ui-researcher for verification by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Tailwind CSS 4 utilities; no component system |
| Preset | not applicable |
| Component library | none; use small local Preact components |
| Icon library | none; use consistent local 20px outline SVGs with `currentColor`, 2px stroke |
| Font | system sans: `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif` |

No `components.json`, Tailwind config, token set, or reusable product component library exists. The Fresh starter styles are scaffolding and are not a visual precedent. Do not initialize shadcn for this Preact/Fresh one-day slice; it adds a React-oriented dependency and setup surface without serving the two-view shell.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Active dot, icon-to-label micro-gap |
| sm | 8px | Inline gaps, compact control padding |
| md | 16px | Page gutters, field and tile padding |
| lg | 24px | View padding and section gaps |
| xl | 32px | Empty-state and sign-in group separation |
| 2xl | 48px | Large vertical separation only |
| 3xl | 64px | Bottom-navigation base height |

Exceptions: interactive controls and nav destinations have a minimum 44px square touch target; circular avatar is 32px inside a 44px target; bottom navigation is `64px + env(safe-area-inset-bottom)` and remains in normal layout flow.

## Typography

Use only these four sizes and exactly two weights across portal-owned UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Supporting / metadata | 14px | 400 | 1.5 |
| Body / controls | 16px | 400 | 1.5 |
| Section heading | 20px | 600 | 1.2 |
| Page heading | 28px | 600 | 1.2 |

Navigation labels use 14px/600. Buttons use 16px/600. Pubkeys use 14px/400 in a monospace fallback, truncated in the middle. Do not introduce lighter than 400, heavier than 600, all-caps labels, or a display size above 28px.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#F8FAFC` | Shell background and page canvas |
| Secondary (30%) | `#FFFFFF` | Bottom navigation, sign-in panel, tiles, notices, fields |
| Accent (10%) | `#7C3AED` | Primary CTA fill, active nav icon/label, active napplet dot, keyboard focus ring |
| Destructive | `#DC2626` | Sign-out action and destructive confirmation only |

Primary text is `#0F172A`; secondary text/icons are `#475569`; borders are `#CBD5E1`; informational/error-notice background is `#FFF7ED` with text `#9A3412`. Accent is reserved for the primary sign-in/connection action, selected navigation state, configured napplet's active indicator, and focus rings. Links and secondary buttons use primary text plus underline/border rather than accent fill. Maintain WCAG AA contrast for portal-owned text and controls.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Connect signer` |
| Nostr Connect instruction | `Scan this QR code with your signer app, or copy the connection URI.` |
| Bunker secondary action | `Use bunker URI` |
| nsec secondary action | `Use nsec` with adjacent badge `Not recommended` |
| Napplet empty state heading | `No napplet configured` |
| Napplet empty state body | `Add a napplet coordinate to the server configuration, then restart Napplet Portal.` |
| Generic shell error | `Napplet Portal could not connect. Check the server and try again.` Action: `Retry` |
| Iframe/handshake error | `The napplet did not start correctly.` Action: `Retry` |
| Integrity error | `The napplet could not be verified and was not opened.` Action: `Retry` |
| Missing capability error | `This napplet requires {capability}, which is not available.` |
| Offline account status | `Signer offline` with support text `Public data can continue updating while Napplet Portal reconnects.` |
| Active stream, initially empty | `Waiting for updates` — do not describe the stream as complete or “no results” |
| Destructive confirmation | `Sign out`: `Sign out of this account? Public data will keep updating, but signing actions will stop.` Actions: `Cancel`, `Sign out` |

Use sentence case. Action labels are verb-first and no longer than three words. Never expose `nsec`, bunker secrets, signer material, raw transport errors, or correlation IDs in ordinary shell copy.

## Layout Contract

- The shell fills `100dvh`, with a `100vh` fallback, and uses a vertical flex/grid layout with exactly two rows: content `minmax(0, 1fr)` and bottom navigation `64px + safe area`.
- The bottom navigation is always in normal layout flow. It consumes layout height, includes `padding-bottom: env(safe-area-inset-bottom)`, and must never use fixed/absolute positioning over the iframe.
- The content row has `min-height: 0` and owns overflow. The open iframe is borderless, full width, and full height of that row. It receives no portal header, card frame, maximum width, margin, or rounded corners, including on desktop.
- The iframe is rendered immediately after successful sign-in. There is no portal loading screen, spinner, skeleton, or completeness gate for napplet/runtime streams.
- Home and Profile are full content-row shell views. Switching to either sets the already-mounted iframe to visually hidden/inert; it does not remove or recreate the iframe. Returning selects the same iframe/content window and preserves in-memory state.
- Home has no header or title bar. It uses 16px mobile gutters and a full-width one-column grid for the single configured napplet tile. At `min-width: 640px`, keep the grid full width but cap each tile at 320px; do not center the whole shell or constrain the napplet viewport.
- Profile uses 16px mobile gutters and 24px vertical padding. It contains active avatar, display name when present, shortened pubkey, signer connection state, and Sign out only. No account switcher, relay/Blossom settings, permissions, or profile editor belongs in Phase 1.

## Component Inventory

| Component | Contract |
|-----------|----------|
| `NappletShell` island | Owns view selection, history integration, WebSocket UI state, and the persistent iframe reference; it contains no backend runtime logic |
| Napplet viewport | Persistent sandboxed iframe using exactly `sandbox="allow-scripts"`; full available content-row size |
| Bottom navigation | Two equal-width destinations: Home and Profile; icon above label; selected state conveyed by color plus semantic current-page state |
| Profile destination | Shows active avatar when available; otherwise a neutral user outline; the label remains `Profile` |
| Napplet tile | Full-width button/card with 48px app icon, one-line name, and a small labeled or accessible active indicator; selecting it reveals the existing iframe |
| Sign-in panel | Nostr Connect is visually primary with QR and copy URI together; bunker URI and nsec are secondary disclosure/options |
| Shell notice | Slim 40–48px notice directly above the visible iframe, in content flow, with one-line message and `Retry`; it reduces iframe height rather than overlaying it |
| Confirmation dialog | Centered modal for Sign out only; focus trapped, Escape/Cancel closes, destructive action uses destructive color |

All controls use native `button`, `a`, `input`, and `dialog` semantics where practical. Disabled controls retain readable labels and expose `disabled`, not only reduced opacity.

## Interaction Contract

1. With no active account, show sign-in in the content row and keep the same bottom-nav footprint; Nostr Connect is expanded first.
2. A successful sign-in immediately makes the new account active and opens the configured napplet. Mount/render the iframe without waiting for account-derived or relay streams to settle.
3. Home and Profile navigation uses a 120ms opacity transition. Respect `prefers-reduced-motion: reduce` by removing the transition. Do not animate iframe geometry.
4. Browser Back while the napplet is visible switches to Home without reload. Selecting the active Home tile returns to the existing mounted iframe. Back must not exit the portal before first returning to Home.
5. Profile destination/avatar opens the general settings/account shell view. This phase exposes active-account details and Sign out only.
6. When identity changes in another tab, update avatar/account content and notify the mounted napplet without remounting it. If signed out, show identity unavailable and reject signing operations; public stream content may remain visible.
7. On iframe load, integrity, session, or handshake failure, retain the iframe and insert the slim notice above it. Retry may re-resolve/reload the napplet explicitly. Ordinary NAP errors remain inside the napplet and do not create shell notices.
8. Copy URI provides immediate feedback by changing the action label from `Copy URI` to `Copied` for two seconds; copying must not navigate or expose the value elsewhere.

## Accessibility and Responsive Acceptance

- Validate at 320px, 390px, 768px, and 1440px widths, plus mobile portrait with a non-zero safe-area inset. No horizontal shell overflow is allowed.
- Every control has a visible 2px accent focus ring with 2px offset; focus order follows visual order. Icon-only avatar controls have `aria-label="Open profile"`.
- Bottom navigation uses `<nav aria-label="Primary">`; active destination uses `aria-current="page"`. Icons are decorative when labels are visible.
- Shell notices use `role="alert"` only when newly introduced; stream updates use a non-interrupting `aria-live="polite"` region and are coalesced to avoid repeated announcements.
- QR code has adjacent text and a copyable URI, so it is never the only sign-in path. Inputs have persistent labels, not placeholder-only labels.
- The 120ms fade is the only portal view animation. Reduced-motion mode removes it.
